# 美分马丁-stable EA 功能文档

> **文件**：`美分马丁-stable.mq5` | **版本**：v1.9 | **平台**：MT5

XAU/USD 美分账户马丁格尔策略，基于 CENT22 真机数据反推的手数序列 + M15 MA20/50 双均线信号。带黑天鹅、点差、新闻窗口、周一开盘四层保护，满层后等待一段时间再决定是否平仓。

> v1.9 参数（间距 3.25 / 24 层）按 **600u（60000 USC）本金**设计。余额不足时面板会红字提示。

---

## 1. 概述

### 定位
- **品种**：XAUUSD.ct（Decode Global 美分账户黄金合约）
- **账户类型**：**必须 Hedging 模式**（多空共存的前提），Netting 账户会 `INIT_FAILED`
- **杠杆**：500:1 计算保证金
- **合约规格**：0.01 手 = 0.01 oz，$1 价差 × 0.01 手 = 1 USC 盈亏
- **建议资金**：v1.9 默认参数按 **$600（60000 USC）**设计；低于该值时 L24 满层前可能先被券商强平

### 策略骨架

```
方向判断 (M15 MA20/50 交叉)
    ↓
[空仓] 首单 0.01 手
[持仓 + 最新单浮亏 ≥ $3.25] 加下一层 (v1.9: 间距 3.25, 实际成交间距 = 3.25 - 点差)
[持仓 + 顺向浮盈 ≥ $0.6/oz 均价差] 该方向 CloseAll 全平
[篮子 ≥ 16 层] 加仓不看信号, 信号翻转不平仓 (v1.9)
[满 24 层] 等待 30 分钟, 期间到 TP 止盈, 到点不论盈亏全平 (v1.9)
[黑天鹅/点差/新闻/周一开盘] 阻断开新仓
```

## 3. 前置要求

### 账户
- **必须 Hedging 账户**（`OnInit` 校验 `ACCOUNT_MARGIN_MODE_RETAIL_HEDGING`，非 Hedging 直接拒启动）
- USC 计价（美分账户）
- 500:1 杠杆
- 最小手数步进 0.01

### 平台
- MetaTrader 5（build 2000+，为了 Calendar API）
- 允许自动交易（`Ctrl+E` / 顶部工具栏"算法交易"按钮开启）
- Broker 需允许 `WebRequest` 到 Calendar API 服务器（可选，缺失时新闻过滤失效）

### 图表
- 品种：XAUUSD.ct
- **周期：必须 M1**（OnInit 强制校验，非 M1 直接 `INIT_FAILED`）
  - 加仓 tick 敏感，M5+ 会漏加仓机会
  - 防止误挂多图表造成同 magic 双实例冲突
- 信号周期由参数 `SignalTimeFrame` 独立控制（默认 M15，跟图表周期无关）

## 4. 参数说明

所有参数分 5 组呈现在 MT5 参数窗。

### 4.1 策略核心（`=== 策略核心 ===`）

| 参数 | 默认 | 单位 | 含义 |
|---|---|---|---|
| `SignalTimeFrame` | `PERIOD_M15` | 枚举 | MA20/50 计算周期 |
| `LossPriceGap` | `3.25` | USD/oz | 加仓触发阈值：**最新一单浮亏** ≥ 此值触发下一层（v1.9: 2.5→3.25）|
| `AvgProfitTarget` | `0.6` | USD/oz | 平仓触发阈值：**该方向加权均价浮盈** ≥ 此值全平 |
| `Inp_MinUsdProfit` | `0.0` | USC | 兜底：均价达标但 USD 浮盈 < 此值时**等待**（0=不启用） |
| `MaxOrderCount` | `24` | 层 | 每方向最大层数（v1.9: 22→24，按 600u 设计） |
| `Inp_MaxLayerClose` | `true` | bool | 满层处理开关（v1.6 引入；v1.9 配合下面的等待时长） |
| `Inp_MaxLayerWaitMin` | `30` | 分钟 | **v1.9**: 满层后等待时长；期间到 TP 照常止盈，到点不论盈亏全平；`0` = 开出满层立即全平（v1.8 行为） |
| `Inp_MaxLayerHardML` | `0` | % | **v1.9**: 等待期硬止损，保证金比例 ≤ 此值立即全平；`0` = 关闭（见 §7.6） |
| `Inp_NoRotateLayer` | `16` | 层 | **v1.9**: 篮子 ≥ 此层数时，加仓不看信号、信号翻转不平仓、不开反向单；`0` = 关闭（v1.8 行为） |
| `MultiAfter4` | `1.3` | 倍率 | **L13+** 每层 = 上一层 × 此倍率（前 12 层查表） |
| `MagicNum` | `8866` | int | 订单 magic number，用于识别本 EA 持仓 |
| `Slippage` | `10` | points | CTrade 允许滑点（Deviation） |

> [!]️ `LossPriceGap` 和 `AvgProfitTarget` 单位是 **USD/oz**（价格差），**不是** 美元浮亏/浮盈。用美元触发请配合 `Inp_MinUsdProfit`。

> [!]️ **实际成交间距 = `LossPriceGap` − 点差**。加仓判断用 Ask（空单）/ Bid（多单）算"最新单浮亏"，但新单成交在另一侧价格，所以每层实际间距比参数小一个点差。点差 0.32 时，3.25 的实际间距约 2.93，24 层铺开约 67.4 点（不是 23×3.25=74.75）。

### 4.2 黑天鹅熔断（`=== 黑天鹅熔断 ===`）

| 参数 | 默认 | 单位 | 含义 |
|---|---|---|---|
| `Inp_BlackSwan` | `true` | bool | 启用黑天鹅熔断 |
| `Inp_BlackSwanRange` | `20.0` | USD | 最近 `Inp_BlackSwanWindowSec` 秒内 tick 最高价 − 最低价 ≥ 此值触发 |
| `Inp_BlackSwanWindowSec` | `60` | 秒 | **v1.9**: 实时检测窗口，按 tick 滚动计算，不等 K 线收盘 |
| `Inp_BlackSwanLayerCap` | `16` | 层 | **分档阈值**：`max(buyCnt,sellCnt) < 此值` 全平+暂停；`≥ 此值` 只推送，逻辑照常（v1.9） |
| `Inp_BlackSwanPauseMin` | `30` | 分钟 | 全平后禁开新仓的时长（黑天鹅浅套、满层平仓共用；暂停期结束自动恢复） |

**逻辑（按层数分档）**：
- **浅套**（`max(buyCnt,sellCnt) < 16`）：**全平止损 + 暂停 30 分钟**（自动恢复，不冻结）
  - 暂停期过后 EA 自动恢复开仓，避免刚平完立刻在同样趋势里再套
- **深套**（`max(buyCnt,sellCnt) ≥ 16`）：**v1.9 只推送，不冻结**，加仓和满层等待照常运行
  - 触发后清空 tick 缓存，要在新窗口内再走满 $20 才会再次触发，不会每 tick 重复推送
  - v1.8 及以前这里会冻结 EA（需重启），导致深层篮子停加、到不了满层、满层处理也不会启动，只剩 TP 或券商强平两个出口。v1.9 修复

**每层开出瞬间浮亏参考（v1.9 默认：间距 3.25、点差 0.32、价 4300）**：

| 层 | 距 L1 | 累计手数 | 浮亏 (USD) | 占 600u |
|---|---|---|---|---|
| L12 | 32.2 | 1.08 | ~$9 | 1.4% |
| **L16** | **44.0** | **3.21** | **~$29** | **4.9%** ← 分档阈值 / 深层起点 |
| L18 | 49.8 | 5.44 | ~$52 | 8.6% |
| L20 | 55.7 | 9.18 | ~$90 | 14.9% |
| L22 | 61.5 | 15.48 | ~$153 | 25.6% |
| L24 | 67.4 | 26.10 | ~$261 | 43.5% |

> 浮亏 = −实际间距 × Σ(手数 × 距最后一层的层数) − 累计手数 × 点差。实盘会因点差波动、滑点有偏差。

**推送手机需要提前配置**：MT5 → 工具 → 主选项 → 通知 → 填 MetaQuotes ID + 启用推送。

### 4.3 点差保护（`=== 点差保护 ===`）

| 参数 | 默认 | 单位 | 含义 |
|---|---|---|---|
| `Inp_MaxSpread` | `60` | points | 点差阈值 |
| `Inp_SpreadBuffer` | `5` | points | 缓冲 |

**效果**：阻断新开仓（首单/加仓都禁），已有持仓的平仓不受影响。

### 4.4 新闻过滤（`=== 新闻过滤 (FOMC/CPI/PPI/NFP) ===`）

| 参数 | 默认 | 单位 | 含义 |

| `Inp_NewsFilter` | `true` | bool | 启用新闻过滤 |
| `Inp_NewsMinBefore` | `30` | 分钟 | 事件前 X 分钟禁开新仓 |
| `Inp_NewsMinAfter` | `30` | 分钟 | 事件后 X 分钟禁开新仓 |

**匹配的事件关键词**（硬编码）：
- FOMC / Federal Funds Rate / Fed Interest Rate
- CPI / Consumer Price Index

- Non-Farm / Nonfarm / Non Farm

## 5. 策略核心逻辑

### 5.1 OnTick 执行顺序

```
1. CheckBlackSwan()          — 每 tick 记录 bid, 检查最近 60 秒波动 (v1.9 实时)
2. GetPositionStat(stat)     — 统计本 magic 的持仓
2b. ProcessPendingClose()    — v1.9: 上次没平完的方向继续平, 有动作则 return
3. 清理 g_buyWaitUsd/g_sellWaitUsd 标志 (C3 用)
4. 平仓判定 (buy)             — 均价浮盈达标 → CloseAllByDir(1)
5. 平仓判定 (sell)            — 均价浮盈达标 → CloseAllByDir(-1)
6. CheckMaxLayerWait()       — v1.9: 满层等待到点 / 硬止损 → 全平 + 暂停
7. emergencyFrozen 检查       — 冻结则 return
8. pauseOpenUntil 检查        — 暂停期内 return
9. IsSpreadOK()              — 点差超限则 return
10. IsNewsBlackout()         — 新闻窗口内则 return
11. IsMonOpenBlock()         — v1.9: 周一开盘保护期内 return
12. 深层篮子 (≥ Inp_NoRotateLayer) — v1.9: TryAddDeepLayer() 不看信号加仓, 然后 return
13. GetSignal()              — 无信号则 return
14. 单向轮换                  — 信号翻转先平对向; 对向没平掉则本 tick return
15. totalPos==0 → 首单       — 按信号开 0.01
16. sig==+1 / sig==-1        — 判断加仓条件 (同 v1.8)
17. UpdatePanel()            — 更新面板
```

> **注意**：TP 平仓和满层到点平仓都在保护门之前，即使处于冻结/暂停/新闻窗口，**仍会执行**。

> **深层篮子与 v1.8 的关系**：第 12 步只在存在 ≥ 16 层的篮子时生效。16 层以下的篮子走第 13–16 步，代码与 v1.8 相同。`Inp_NoRotateLayer = 0` 时第 12 步整段跳过。

### 5.2 方向信号（`GetSignal()`）

```mql5
maFast = MA(20, PRICE_CLOSE, shift=1)   // 已收 bar
maSlow = MA(50, PRICE_CLOSE, shift=1)
if maFast > maSlow  return +1  (做多)
if maFast < maSlow  return -1  (做空)
return 0
```

**v1.3 优化**：从 `shift=0` 改为 `shift=1`，用**已收 K 线**避免未收 bar 每 tick 抖动。

### 5.3 首单开仓

条件（同时满足）：
- `totalPos == 0`（无本 magic 持仓）
- `sig != 0`（有方向信号）
- 未处于冻结 / 点差过大 / 新闻窗口

执行：`OpenTrade(sig, fixedLotArr[0]=0.01, layer=1)`

### 5.4 加仓机制（v1.4 核心改动）

**触发条件（分方向）**：

**多单加仓**（`sig==+1` 且 `buyCnt < MaxOrderCount`）：
```
lastOpen = GetLastOpenPriceByDir(+1)   // 最新一单开仓价
lastLoss = lastOpen - Bid              // 最新单浮亏 (>0 表示亏)
if lastLoss >= LossPriceGap:
    加多一单
```

**空单加仓**（`sig==-1` 且 `sellCnt < MaxOrderCount`）：
```
lastOpen = GetLastOpenPriceByDir(-1)
lastLoss = Ask - lastOpen              // 最新单浮亏 (>0 表示亏)
if lastLoss >= LossPriceGap:
    加空一单
```

**下一单手数**：
```
if 已开层数 < 12:  查 fixedLotArr[已开层数]     (L1-L12)
else:              上一单手数 × MultiAfter4    (L13+)
```

**v1.4 关键改动**：从"加权均价浮亏"改为"**最新一单浮亏**"，让每层间距恒定。

旧版（v1.3 及以前）问题：均价被大手数快速拉动，L5-L12 实际间距 $0.4-0.8，12 层挤在 $6 里。

**实际成交间距 = `LossPriceGap` − 点差**：判断用 Ask（空）/ Bid（多），成交在另一侧价格。11-03 真机 gap 2.5 篮子实测相邻层成交价差 2.18–2.42，平均约 2.3，与 2.5 − 0.2 吻合。v1.9 默认 3.25、点差 0.32 时实际约 2.93，24 层铺开约 67.4 点。

**深层篮子（v1.9）**：篮子 ≥ `Inp_NoRotateLayer`（16）层后，加仓改由 `TryAddDeepLayer()` 处理，**不看信号**，条件仍是"最新单浮亏 ≥ `LossPriceGap`"，手数规则不变，直到满层。冻结、暂停、点差、新闻、周一开盘仍会阻断加仓。

### 5.5 平仓机制

**触发条件（分方向独立）**：

```
buyAvgProfitPrice = Σ((bid - openPrice[i]) × lot[i]) / Σ(lot[i])   // 多单方向加权均价浮盈
if buyAvgProfitPrice >= AvgProfitTarget:
    if Inp_MinUsdProfit > 0 && USD 浮盈 < Inp_MinUsdProfit:
        等待 (记 g_buyWaitUsd, 日志节流打印一次)
    else:
        CloseAllByDir(+1)   // 一次性平掉所有多单
```

空单镜像。

**平仓不受**：`emergencyFrozen`、暂停、点差、新闻、周一开盘 这些保护门的阻断。
**平仓不看**：MA 信号（即使信号翻转也允许自然止盈）。

**平仓重试分级（v1.9）**：`CloseAllByDir()` 每单最多试 10 次，按错误类型处理：

| 错误类型 | 返回码 | 处理 |
|---|---|---|
| 持仓已不存在 | — | 每次重试前先 `PositionSelectByTicket`，找不到就**按已平计**（券商同时强平、上次超时但已成交等） |
| 环境错误 | `MARKET_CLOSED` / `TRADE_DISABLED` / `SERVER_DISABLES_AT`(10026) / `CLIENT_DISABLES_AT`(10027，手动关了"算法交易") | 立即停止本轮，不计失败、不冻结，下个 tick 再试 |
| 瞬时错误 | `REQUOTE` / `PRICE_CHANGED` / `PRICE_OFF` / `CONNECTION` / `TIMEOUT` / `TOO_MANY_REQUESTS` | 每次间隔 200ms，本轮失败也不冻结，下个 tick 再试 |
| 其他错误 | — | 10 次全失败 → 冻结 EA + 推送，需人工处理 |

v1.8 不区分错误类型，满层等待如果恰好在每日停盘时到期，会瞬间失败 10 次并冻结 EA。

**未平完的处理**：一次 `CloseAllByDir` 里如果有单暂缓，该方向记为"待平"。下个 tick 一开始（在 TP 判断之前）由 `ProcessPendingClose()` 继续平，平完之前本 tick 不做其他事（不开仓、不加仓）。这样不会出现"平掉一半，剩下的单子被当成新篮子继续加仓"的情况。满层平仓如果没一次平完，会等全部平完后才推送结果并开始暂停期。面板状态行显示 `[WAIT] 平仓暂缓 ...`。

### 5.6 单向轮换（v1.8 新增，v1.9 深层例外）

信号翻转时，`OnTick` 在开新方向仓位之前先执行 `CloseAllByDir(对向)`：

```
信号由多→空：先 CloseAllByDir(+1) 清多仓 → 再按空单逻辑加仓
信号由空→多：先 CloseAllByDir(-1) 清空仓 → 再按多单逻辑加仓
```

- 每个时刻只有**一个方向**承担马丁风险
- 对向止盈时自然平仓，信号未翻转则不强制清仓
- 平仓后刷新 `stat`，确保 `totalPos` 准确
- **v1.9**：对向仓位因暂缓或冻结没平掉时，本 tick 不开新方向，避免多空同时持仓
- **v1.9 深层例外**：篮子 ≥ `Inp_NoRotateLayer`（16）层时**不轮换**，信号翻转不平仓，也不开反向单，篮子继续按间距加仓直到 TP 或满层

## 7. 保护机制

### 7.1 Hedging 账户校验

在 `OnInit` 首步：
```mql5
if(AccountInfoInteger(ACCOUNT_MARGIN_MODE) != ACCOUNT_MARGIN_MODE_RETAIL_HEDGING)
    return INIT_FAILED;
```
Netting 账户直接拒运行，因为策略依赖多空共存。

### 7.2 黑天鹅熔断（v1.5 按层数分档，v1.9 实时检测 + 深套不冻结）

每个 tick 首先执行 `CheckBlackSwan()`：

```mql5
记录当前 bid 到环形缓存, 丢弃 Inp_BlackSwanWindowSec (60) 秒之前的 tick
range = 缓存内最高价 - 最低价
if range >= Inp_BlackSwanRange:
    清空缓存                               // v1.9: 新窗口内再走满阈值才会再次触发
    maxLayer = max(buyCnt, sellCnt)
    if maxLayer < Inp_BlackSwanLayerCap:
        // 浅套: 全平止损 + 暂停 X 分钟 (自动恢复, 不冻结)
        CloseAllByDir(+1); CloseAllByDir(-1)
        pauseOpenUntil = TimeCurrent() + Inp_BlackSwanPauseMin * 60
        Alert(...); SendNotification(...)
    else:
        // 深套 (v1.9): 保留持仓, 只推送, 不冻结, 加仓/满层等待照常
        Alert(...); SendNotification(...)
```

**两种行为对比**：

| 分档 | max(buyCnt,sellCnt) | 行为 | 恢复方式 |
|---|---|---|---|
| 浅套 | < 16 | **全平 + 暂停 30 分钟** | 暂停期结束自动恢复 |
| 深套 | ≥ 16 | **只推送**（v1.8 为冻结） | 无需恢复，逻辑一直运行 |

**v1.9 为什么改**：v1.8 深套冻结后，篮子不加仓、不轮换、到不了满层，满层处理也不会启动，只剩 TP 或券商强平两个出口，相当于把篮子丢给运气。改为只推送后，深层篮子继续加到满层，由满层等待机制收尾。

**实时检测的特点（v1.9）**：
- 每个 tick 都看最近 60 秒的波动，价格一走满 $20 就触发，不等 M1 收盘；跨分钟边界的急涨急跌也能抓到。v1.8 看的是已收盘的上一根 M1，最多晚 1 分钟，这 1 分钟里按 3.25 间距能多加 6～7 层。
- 只看波幅不看方向：先急涨 $20 再回落的行情，也会在急涨那一刻触发。
- 触发更早，层数判断也更早：同一波行情，篮子更可能在 16 层以下就被判为浅套全平，而不是等加到 16 层以上变成只推送。
- 缓存只在内存里，EA 重启或改参数后前 60 秒的数据不完整，灵敏度略低。休市前的 tick 早已超出窗口，开盘跳空不会被算成黑天鹅。

**平仓不受暂停期影响** —— 暂停期内已有持仓的自然止盈仍能触发（`pauseOpenUntil` 检查在平仓判定之后）。

**深套告警需要手机推送提前配好**：MT5 → 工具 → 主选项 → 通知 → 填 MetaQuotes ID。

### 7.3 点差过滤

`IsSpreadOK()`：`spread > Inp_MaxSpread + Inp_SpreadBuffer` 时禁开新仓（不影响平仓）。
状态变化时打印一次日志：`[!] 点差过大 XXX > 65 → 禁开新仓` / `✓ 点差恢复正常`。

### 7.4 新闻过滤

`IsNewsBlackout()`：
1. **缓存 60s**（`g_newsCacheTs`），避免每 tick 拉外部日历
2. 查询 `now-30min` 到 `now+30min` 内所有 US 事件
3. 筛选 `CALENDAR_IMPORTANCE_HIGH`
4. 关键词匹配 FOMC/CPI/PPI/NFP → 返回阻断

`OnInit` 首次调用探测 Calendar API 可用性，失败时打印警告（broker 服务器不共享日历时会失败）。

### 7.5 开单失败节流

`OpenTrade()` 失败后：
1. **致命错误**（`NO_MONEY`/`LIMIT_VOLUME`/`LIMIT_ORDERS`/`LIMIT_POSITIONS`）→ 立即 `emergencyFrozen=true` + Alert
2. **环境错误**（`MARKET_CLOSED`/`TRADE_DISABLED`）→ 走冷却，打印时加标签
3. 其他错误 → 走冷却

冷却期 `Inp_OpenFailCoolSec` 秒内同错误只打印 1 次。

### 7.6 满层处理（v1.6 新增，v1.9 改为等待）

`Inp_MaxLayerClose = true` 时，按 `Inp_MaxLayerWaitMin` 分两种模式：

**等待模式（v1.9 默认，`Inp_MaxLayerWaitMin = 30`）**：

1. `OpenTrade()` 开出第 `MaxOrderCount` 层（默认 L24）时，不平仓，只推送"满层，等待 30 分钟"
2. 等待期间每 tick 正常判断 TP，到 TP 就止盈全平
3. `CheckMaxLayerWait()` 每 tick 检查：该方向层数 ≥ `MaxOrderCount` 且**最后一单开仓后已经过 30 分钟交易时间** → 不论盈亏全平
4. 全平后暂停开新仓 30 分钟（`Inp_BlackSwanPauseMin`），并推送一次（内容是**触发平仓时的浮盈**，不是最终成交结果；平仓因停盘等原因推迟时两者可能相差较多，以账户历史为准）
5. 面板状态行显示 `[WAIT] 满层等待 剩 X 分钟`

计时起点是最后一单的开仓时间，**只计交易时间**：按起点之后生成的 M1 K 线根数计算，休市期间（每日停盘 23:59–01:00、周末、节假日）不生成 K 线，所以不计入。例如 L24 在每日停盘前 10 分钟开出，开盘后还会再等约 20 分钟，而不是开盘第一个 tick 就按跳空价全平。交易时段内个别没有成交的分钟也不计，所以实际等待可能略长于设定值。因为直接读 K 线历史，EA 重启后能接上；K 线历史取不到时退回按服务器时间差计算。到点平仓和 TP 一样在保护门之前执行，不受冻结、暂停、新闻、点差影响。平仓遇到市场关闭或瞬时错误时，下个 tick 继续尝试（见 §5.5）。

**立即模式（`Inp_MaxLayerWaitMin = 0`，即 v1.8 行为）**：开出满层的那一刻立即全平 + 暂停。

**等待期硬止损（`Inp_MaxLayerHardML`，默认 0 = 关闭）**：等待期间账户保证金比例 ≤ 此值时立即全平，不等到点。参考值（600u、gap 3.25、24 层、点差 0.32、价 4300）：

| 设置 | 触发位置（L24 后再走） | 约亏 |
|---|---|---|
| 不等待，立即全平 | 0 点（L24 开出，保证金比例约 149%） | $261 |
| `100` | 约 4.3 点 | $372 |
| `80` | 约 6.0 点 | $417 |
| `0`（关闭） | 约 8.6 点后券商 50% 强平 | $486 + 滑点 |

硬止损值必须高于券商强平线（Decode 约 50%），否则不会先于强平触发。

硬止损读的是 `ACCOUNT_MARGIN_LEVEL`，是**全账户口径**。同一账户里如果还有手动单或其他 EA 的持仓，实际触发位置会和上表不同。

**等待的取舍**：最好情况是等待期间回弹约 10.6 点到 TP，从 −$261 变成 +$15.66；最坏情况是继续逆行约 8.6 点被券商强平，亏约 $486。不开硬止损时，最坏情况比立即全平多亏约 $225。

**历史背景**：09-16 爆仓根因是 L22 后价格继续走 $11，Margin Level 从 149% 掉到 30%，被 broker stop-out（−$290+）。v1.6 引入满层立即全平，把这类亏损限制在开出满层那一刻。

### 7.7 冻结状态 / 暂停期（v1.5 分离）

**`emergencyFrozen = true`（冻结，永久性）**：
- **阻断**：新开仓（首单、加仓）
- **不阻断**：自然止盈平仓、满层到点平仓（平仓失败冻结时除外）
- **触发场景**：开仓致命错误（`NO_MONEY` 等）/ 平仓"其他错误"10 次全失败
- v1.9 起**黑天鹅深套不再冻结**
- 面板显示：`[!]致命错误冻结 (需重启 EA)` 或 `[FATAL] 平仓失败10次 ...`
- **解锁**：重新加载 EA（拖回图表 / 重启 MT5），或在属性窗口点确定（v1.9 的 `OnInit` 会同时清掉平仓失败和待平状态）
- **注意**：开仓报 `NO_MONEY` 冻结时，篮子停在当前层，到不了满层，满层等待不会启动，只剩 TP 或券商强平。v1.9 默认参数按 600u 设计，余额不足时需人工监控

**`pauseOpenUntil` 暂停期（临时性）**：
- **阻断**：新开仓（首单、加仓）
- **不阻断**：自然止盈平仓
- **触发场景**：黑天鹅浅套（< `Inp_BlackSwanLayerCap`）全平后 / 满层平仓后
- 面板显示：`[PAUSE] 暂停开仓 剩 X 分钟`（橙色）
- **解锁**：暂停期结束（`Inp_BlackSwanPauseMin` 到点）**自动恢复**

```
[stable] ❌ 开单失败 dir=-1 lots=0.01 rc=10027 auto trading disabled by client (2s 内重复失败仅记 1 次)
```

**致命错误**：
```
[stable] ⛔ 致命错误 rc=10019 no money dir=-1 lots=3.56 → 冻结 EA
```

## 11. 已知限制 & 风险

### 11.1 电脑重启 / EA 掉线
- EA 不运行时**无法处理持仓**（既不加仓也不平仓）
- 恢复后 `GetPositionStat` 能识别原有持仓，但**期间价格走势已固化**
- **根本解决**：VPS 部署 24/7 运行

### 11.2 单边趋势市
- 马丁核心假设是"深套后会反弹"
- 极端单边行情下：
  - 满层后无法再加仓
  - 平仓门槛远在均价 + $0.6/oz 处，等不到
  - 账户浮亏持续放大直至满层到点平仓或券商强平
- **v1.9 默认参数（600u、gap 3.25、24 层、点差 0.32）**：
  - L24 在 L1 起约 67.4 点开出，满层回本需回弹约 10.6 点
  - 关闭满层处理时，约 76 点被券商 50% 强平
- 不同间距下的能扛点数（600u、24 层、倍率 1.3、点差 0.32）：

| gap | 实际间距 | L24 开仓位 | 满层立即平约亏 | 50% 强平位置 | TP 回撤 |
|---|---|---|---|---|---|
| 2.50 | 2.18 | 50.1 | $196 | 61.3 | 8.1 |
| 3.00 | 2.68 | 61.6 | $239 | 71.1 | 9.8 |
| **3.25** | **2.93** | **67.4** | **$261** | **76.0** | **10.6** |
| 3.50 | 3.18 | 73.1 | $282 | 80.9 | 11.4 |
| 4.00 | 3.68 | 84.6 | $325 | 90.8 | 13.1 |

- 真实单边参考：9-11 约 59 点、9-16 约 55–66 点、11-03 约 72 点、9-22 全天振幅约 84 点
- 每轮 TP 收益只与层数有关：满 24 层约 $15.66（AvgProfitTarget 0.6 × 26.10 手）

### 11.6 满层等待的最坏情况（v1.9）
- 不开硬止损时，等待期继续逆行约 8.6 点会被券商 50% 强平，约亏 $486 + 滑点，比满层立即平多亏约 $225
- 周末跳空可能直接越过强平线，周五收盘前需人工停止开仓、确认没有深层篮子
- 等待只计交易时间，满层篮子会**带着仓位跨过每日停盘或周末**。停盘期间 EA 什么也做不了，开盘跳空的风险由持仓承担；跨周末的情况只能靠周五人工处理

### 11.3 L1 亏损结构
- L1 胜率 66.7%（每 3 次赢 2 次）
- 但**盈亏比 1:2**（亏损单是盈利单 2 倍大）
- 因为**L1 是空单里位置最不利的一层**，深套 CloseAll 时 L1 必然是亏损单
- 这是马丁的**固有代价**，无法通过参数调整消除

### 11.4 新闻过滤依赖 Calendar API
- Broker 服务器不共享日历时 `CalendarValueHistory` 返回 <0
- `OnInit` 会打印警告，但**新闻过滤会静默失效**
- **建议**：启动后手动确认工具栏"日历"能显示未来事件

### 11.5 双向共存
- v1.8 起单向轮换，正常情况下只有一个方向持仓
- 理论最坏仍可能出现两个方向同时持仓（例如轮换时对向平仓暂缓），v1.9 在这种情况下本 tick 不开新方向

## 13. 常见问题（FAQ）

**Q1：为什么 EA 挂上后一直报 err=10027？**
A：MT5 顶部"算法交易"按钮没开。`Ctrl+E` 或点击工具栏该按钮打开。

**Q2：为什么启动日志说"Calendar API 读取失败"？**
A：Broker 服务器不共享 MQL5 日历数据。新闻过滤不生效，需人工避开 FOMC/CPI/PPI/NFP 时段。

**Q3：为什么日志里连续开单失败刷屏？**
A：v1.2+ 已加冷却（默认 2s）。如果仍频繁，看具体错误码。

**Q4：满 24 层了怎么办？**
A：v1.9 默认等待 30 分钟。期间到 TP（均价浮盈 ≥ $0.6/oz）就止盈；30 分钟到点不论盈亏全平，然后暂停开仓 30 分钟。面板会显示倒计时，手机会收到两次推送。如需提前处理可人工平仓。

**Q5：`Inp_MinUsdProfit` 和 `AvgProfitTarget` 什么区别？**
A：`AvgProfitTarget` 是**价格差**（USD/oz）。`Inp_MinUsdProfit` 是**账户货币浮盈**（USC）。两个都达标才平仓。默认 `Inp_MinUsdProfit=0` 即不启用兜底，只看价差。

**Q6：为什么加仓从 L12 到 L13 是 0.35 手（不是 0.351）？**
A：`NormalizeLot` 用 `MathFloor` 向下取整到 broker step。0.27 × 1.3 = 0.351 → floor 到 0.35。

**Q7：EA 重启后能接管原有持仓吗？**
A：能。`GetPositionStat` 按 `MagicNum` 识别本 EA 持仓，重启后继续按当前 sellCnt/buyCnt 判断加/平仓。但**期间价格波动无法追回**。

**Q8：能同时挂多张图跑同一个 EA 吗？**
A：**不能**。两个 EA 共用同一 `MagicNum` 会互相干扰持仓统计。想跑多品种/多方向请用不同 `MagicNum`。
